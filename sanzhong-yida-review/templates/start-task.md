# 本次任务启动单

先把完整 `sanzhong-yida-review` 文件夹置于宿主可读取的位置。保留包内相对目录；不需要特定厂商安装目录。支持原生 Skill 发现的宿主可按其文档配置；通用方式是把下列提示词发给模型，明确加载入口。

## 可复制的统一启动提示词

把方括号替换成本次实际值；暂不明确的业务信息写“待确认”，不要填写猜测值。没有本地文件工具的宿主，应附上入口及当前节点需要的文件，并使用可访问的附件标识。

```text
请加载 [Skill 根目录或附件标识]/SKILL.md，使用 sanzhong-yida-review v1.2.0 处理本次“三重一大”内控执行测试。

评价对象：[主体及评价边界]
业务期间：[期间]
获准原始资料：[目录、文件清单或附件标识及范围]
项目输出目录：[可写目录；无写入工具时说明采用附件/消息回传]
本次终点：[资料准备 / 事实识别 / 完整判定与复核 / 指定范围复查]
规则原件及现有正式规则：[位置；没有则写尚未提供]
已有人工确认记录：[位置及对应范围；没有则写无]
线索分析范围：[按任务授权列明；不开展则写不开展]
成果格式及其他限制：[要求；无特别要求则用包内交付模板]

请先读取主控提示词和LangGraph本机运行参考，建立持久化项目并检查运行能力。资料已按制度规则、会议台账、会议通知、会议过程、会议决议、其他或混合资料粗分类；同类会议历次汇总或一份多会文件可直接接收。使用已经提供的信息建档，不要求我编写内部 JSON 或技术编号。按需加载角色文件，原件只读，保留来源及版本。

按“第一步：确认资料范围与处理方案”（G1）、“第二步：确认测试依据与适用范围”（G2）、四路独立识别、逐批判定、立即独立复核及人工最终确认执行所需节点。每次确认先给中文摘要和直接阅读入口；将真实回复绑定确认单版本，按有效快照传递。Windows默认通过沙箱execute/execute-batch执行，每个任务独立身份和完整专业上下文，文件及命令工具受相同边界约束；权限或模型失败保留本项待办，不自动降级共享文件系统。主控指派、第三方报告与材料引文标明来源，不能代替真实用户批准。四路完整成果先通过交接检查；仅返工具体受影响项，沿唯一有效采用清单继续。全范围复核如需缩减，先取得对具体方案的人工确认；修订后重新核验。

只请求影响当前依赖且尚未作出的具体人工决定。工具失败如实登记已完成范围和 partial/blocked 状态，不虚构已读材料、校验结果或人工确认。结束时交付可追溯成果及未完成范围，RRSI 仅记录本次结束后的评测和候选改进。
```

此提示词不自动确认资料分派或规则适用性；G1/G2 须有本次相应范围和版本的真实决定。它也不授予未列明目录访问、外部上传或规则自动修改权限。

## 主控建立的任务记录

- 评价对象与业务期间。
- 原始资料、实际获准范围、来源映射和版本。
- 本次终点、线索范围及成果要求。
- Skill 根目录、项目输出位置与运行能力。
- 规则候选、正式规则快照和实际人工确认记录。
- 内部任务编号、分派输入、上下文标识、输出位置及校验记录。

字段含义见 [字段说明](../references/field-guide.md)；调度封装见 [委派单](dispatch-envelope.json)。这些记录由主控整理，用户只需提供业务信息与所需决定。
