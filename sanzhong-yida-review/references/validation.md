# 校验与复核

运行时检查按下列职责执行。发布版本的实际验证结果见[发布验证记录](release-validation.md)。

## 文件包检查

在解压后的仓库目录执行：

```text
python -B -X utf8 sanzhong-yida-review/scripts/check_package.py
```

脚本仅使用 Python 3.10 及以上版本的标准库，检查角色文件、字段归属、规则目录、JSON、相对链接、发布摘要和提取回归。默认只向标准输出返回 JSON，不改写规则或运行资料。需要留档时用 `--output` 指定新的包外记录路径。

## 四路提取成果检查

```text
python -B -X utf8 sanzhong-yida-review/scripts/validate_result.py result.json --task task.json
```

每一路独立运行。任务输入和成果必须来自同一 task_id、run_id、agent_name、meeting_package_id。校验器核对结构、字典归属、部分证据引用、白名单、字段状态及完成条件；失败时保留错误并退回原角色，不由主控改写业务事实。

程序不验证原文真实性、完整阅读、业务语义或文件访问隔离。JSON 通过不能证明评价结论正确；日期、金额限定、条件和版本仍需独立回看原件。判定和复核成果按对应提示词的交接契约审阅，本包不提供完整的自动业务判定校验器。

## 更换运行模型

先按[运行适配协议](runtime-adapter.md)确认文件读取、独立上下文、白名单及成果留存能力。使用合成材料进行小样本演练，再与评价人员的核验结果对照。只改变模型也要登记新运行编号、实际模型信息、提示词与规则摘要；不沿用旧运行的通过结论。

没有可执行的独立上下文或资料隔离方式时，生成委派包交给独立会话处理。不能在一个已看过全部结论的会话中切换角色并称为独立复核。

## 规则及协议维护

修改规则后核对触发、字典、比较口径、正常解释、证据不足边界和原件引用。字典、提示词、规则和运行采用清单分别记录版本。局部返工按工作流中受影响单元的依赖重做；不能让旧复核继续为已改变的事实或结论背书。

正式发布指文件包的版本状态。每个项目仍须完成本次资料和规则确认、原件核验及评价人员最终认定。
