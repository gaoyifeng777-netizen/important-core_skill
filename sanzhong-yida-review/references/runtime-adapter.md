# 宿主能力与任务桥接

宿主适配说明1.2.0，包版本1.2.0，图传输协议1.0。默认[LangGraph本机运行](langgraph-runtime.md)配合[逐任务沙箱](sandbox-execution.md)；本文件说明角色实际由谁执行及隔离边界。

## 默认Windows沙箱执行

Python图生成任务，主控调用execute/execute-batch。适配器为每任务创建AppContainer，新专业agent loop及其全部工具在受限进程中执行；主控只转发固定远程模型推理请求并收集完整成果。真实执行和校验回执交回图后才采用，不能把生成待办视为已执行。

主控读取pending任务的冻结task.json与input.json，执行器只复制对应role_prompt、业务输入、获准材料及必要运行依赖。识别任务不附主控历史、其他识别输出、制度规则或预期答案。独立身份/上下文来自host实际创建的SID、PID和attempt，而不是worker自报；receipt绑定输入/输出hash、边界检查及实际模型执行。回执仍是可信宿主记录，不是对任意恶意宿主的密码学证明。

默认不提供主机通用文件/终端/connector旁路，角色网络关闭；自己阅读件可读，其他角色和主控私有数据不可读，输入不可修改、输出可写。检查失败、模型服务异常或环境不可用只阻塞本项，不切换到共享文件系统。无需公司系统、WSL、Docker、回环权限或全局ACL修改。

显式旧配置execution_mode=codex_external_bridge保留1.1.0的原生fork_turns:none传输；此模式共享文件系统，只能称最小输入/指令约束。不得为了绕过失败擅自选择它，已有旧项目也不会随包升级自动获得硬隔离。新平台适配先使用虚构材料验证，不能把同目录或接口兼容宣称为权限验收。

混合文件只向角色提供可追溯的分范围阅读件或明确可用范围；无法可靠限定内容时保留待准备状态。粗分类目录不是已核实事实；资料接收集合可以跨多场会议，实际会议身份由原件支持。

## 能力检查与失败处理

| 能力 | 实际要求 | 不具备时 |
|---|---|---|
| 读取材料 | 读取获准文件/附件，留原件位置和失败范围 | 用获准派生件；仍不可读则记录限制 |
| 独立上下文 | 每任务新上下文、关闭历史继承 | 转交全新独立会话/API；等待期间不报已执行 |
| 等待收集 | 按任务、运行、角色和实际句柄收原始成果 | 保留未完成范围，不能主控补写 |
| 人工确认 | 展示具体版本及可读内容，留真实回复 | 只暂停依赖此决定的工作 |
| 持久化和校验 | 运行器doctor通过、保存SQLite与任务原文 | 修复环境或交付明确阶段成果，不能绕过关口 |

本机默认由可信host使用当前Codex文件登录转发模型推理，角色无登录副本，模型选择来自实际配置。缺失文件登录或模型配置时记录明确限制，不要求用户再给一份API密钥绕过；其他宿主的模型、认证、授权材料范围及OS后端须分别适配。迁移测试使用虚构材料，不上传客户资料试调用。

图任务的spec/receipt/gate_refs作为传输侧页，传统业务输入输出保持对应提示词协议。旧[委派单](../templates/dispatch-envelope.json)仍可用于人工或独立会话传递，版本与运行模式如实填写；角色结果不因换外层协议而重标历史版本。

工具失败保留真实响应、位置和退出码。有限重试不得扩大授权范围，重识别使用新上下文、新run，旧输出保留。结构修复不称独立业务复核。用户停止时保存阶段成果和未完成范围；具体命令见运行参考。

四路schema1.1结构检查可单独执行：

```text
python scripts/validate_result.py "角色结果.json" --task "角色输入.json"
```

此标准库校验不证明已读、事实语义正确、真实人工确认、独立上下文或硬隔离。LangGraph增加交接、确认及采用控制，业务正确性仍须独立实质复核。
