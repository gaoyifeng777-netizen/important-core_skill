# “三重一大”业务执行测试判定逻辑

判定逻辑版本：1.2（对应任务输入 `logic.version=1.2`；适配 Skill 1.0.0、字典1.1、判定schema1.3）；文件性质：通用判定方法与测试设计。适用角色：rule_judge，并供 base_rule 整理规则、quality_review 复核使用。

本文件没有使用真实客户业务资料，不代表已确认任何企业的制度、组织结构、会议权限、数值标准及实际执行情况。本文测试卡是本 Skill 的评价设计，不能作为新增企业义务，也不能替代规则原文。正式结论和缺陷定级由评价人员按照适用权限确认。

## 一、文件定位、输入边界与两个人工闸门

### 1. 与包内文件的关系

| 文件 | 本次用途 | 不可替代的内容 |
|---|---|---|
| `prompts/rule_judge.md` | 判定角色、输入输出、执行状态、引用和退回约束 | 不提供企业实体规则 |
| `rules/business_rules.md`（rule_catalog） | 固定版本CONTROL候选与LEAD方法目录 | CONTROL候选不代替正式要求；LEAD依获准范围使用 |
| 本次运行的rules快照 | 经人工确认的正式控制规则及版本 | 与目录库分开；待确认候选不能直接支持确定性偏差 |
| 本文件 | 将适用规则和独立事实转换为检查单元、比较和初步判定 | 测试设计不能冒充制度条款 |
| `references/fact_dictionary.json` | 四路提取字段及规范化、限定语义 | 字段名称和枚举以已固定的字典版本为准 |
| `references/四路字段字典与串联比较.md` | 字段解释与串联比较示例 | 比较结果不等于业务结果 |
| `references/workflow.md` | 人工闸门、角色路由与版本交接 | 主控不得通过整理输入改写事实 |

引用字段必须来自本次字典。`records.values.items` 的每项包括 `field`、`raw`、`normalized`、`qualifiers`、`evidence_indexes`；`item_index` 是该记录 items 数组的零起始位置。判定引用至少能够回到 `(run_id, record_id, item_index)`，再经证据索引回到文件及位置。`normalized=null` 不等于事实不存在；不得用其他路事实补成规范值。变更提取版本时保留原运行及其索引，不能让同一引用悄然指向新内容。

### 2. 四路资料严格独立

| 提取角色 | 获准来源 | 本路可以形成的事实性质 |
|---|---|---|
| meeting_schedule | 会议通知、议程、清单及明确分派的相应附件 | 拟安排、告知、目录记载；不证明实际讨论或通过 |
| proposal_extract | 申请、审批、议案及相应附件 | 提议内容、报审经过、测算、方案和材料记载；不以“拟”替代“已” |
| meeting_record | 原始会议记录及明确属于记录的附件 | 实际出席、发言、表决、会议结论和条件的记录 |
| meeting_minutes | 会议纪要、决议及相应更正文件 | 正式传达的决定、条件、责任、时限及更正记载；不证明已执行 |

按实际交付的整场会议资料包组织工作，一包可含多个议题、多个文件和多个版本。整会打包不取消四路分派：混合文件先明确页码、附件或段落边界；四路不接收其他路成果、混合共享事实表或预设疑点。只有 judge 汇集四路结果、确认关联并开展比较和规则判断。主控可以编索引、校验引用、固定版本和转交中性复查请求，不改写原始事实，不预先替 judge 归并事项。

### 3. G1 资料闸门

人工处理须明确评价主体与期间、整会包清单、文件性质和版本、混合文件分派、可读性和定位、允许跨会议查阅范围、未提供资料及本次终点。对受限范围不下发任务；不受影响范围可以先做。补证扩大范围或改变分派时，保留新的人工处理记录。

四路未全部有资料不必阻止其他可执行检查，但必须分别报告未提供、未分派、未提取、不可读、已提取未找到等状态。不得把这些状态统称为“企业没有履行”。

### 4. G2 规则闸门

每条规则须有来源性质、原件位置、适用主体、事项条件、发生时有效版本、具体要求、例外、判断参数和人工确认范围。规则来源可以是企业章程、授权、制度，也可以是经核实且确实适用的外部强制要求；由 base_rule 整理并经人工闸门纳入本次正式规则。

企业内部制度缺失不免除明确适用的外部强制要求；企业确认也不能排除或降低强制法律要求。内部制度、外部规定发生冲突，或外部来源的现行效力和历史适用存在疑问时，保留冲突并退回规则处理，不由 judge 自行选择较宽要求。应用指引的示范措施、评价人员拟定的测试方法与法律强制义务分别登记。

没有已确认的通知天数、表决比例、金额阈值、重大调整标准等参数，不猜填。只有规则明确而本次事项事实缺失时，结果才是“证据不足”；规则含义、效力或适用边界待定时为“规则待确认”。

## 二、逐步判定流程

### 第 1 步：固定本次输入与可执行范围

读取任务身份、资料闸门、规则闸门、字典和提示词版本；登记四路每个 run、会议包及 source_key 映射。两个不同 run 的同名 file_id 或 record_id 不自动同源。保存完整上游输出与 coverage，不只读取疑点摘要。没有任何可执行单元时按角色提示词返回 blocked；有可用范围时继续处理并保留限制。

### 第 2 步：按真实会议建立目录，再在 judge 内部关联事项

1. 先以会议主体、会议机构、届次/次数、实际或计划时间、文件交叉引用核对会议身份。相同“第 5 次”不证明同一会；通知时间与实际召开时间分开。
2. 在每场会议中保留原议题顺序、撤回、延期、合并、拆分和补充议题，再结合事项编码、项目、相对方、标的、金额语义和明确交叉引用形成事项关联。
3. 将关联标为 confirmed、candidate 或 unlinked，并写支持及冲突依据。标题相近、相邻日期、相同金额只是辅助；不存在“满足两项就必定同事项”的机械门槛。
4. 一个事项可以在多场会议讨论，一场会议也可以涵盖多个事项；允许一对多、多对一及阶段性决定。不得强制党委会、总办会、董事会一一对应，不以次数、频次或议题顺序对应推导完整性。
5. 同一计划、预算或采购需求组下不同事项使用 same_group，保留各自 matter_id。累计比较说明成员、共同范围、期间、排除项及依据；同组不证明同事项、适用累计义务或人为规避。
6. 只有已确认规则要求某一事项经某主体按某顺序履行程序，才建立该路径。不得预设“党委→总办→董事会”必经链；授权决策、研究讨论、审议、审批、报告和执行各有性质，不能互换。

candidate 可支持中性补证。依赖关联成立的确定性业务结果，须先取得足以确认关联的依据；其他独立单元可继续。

### 第 3 步：建立检查单元和必要事实清单

检查单元通常为“事项 × 规则 × 阶段”，会级要求可先按整会核验，再把适用结果引用到议题，避免重复计数。每张测试卡只选择本次适用、获准的部分，并绑定实际 rule_id；T01—T14 是方法编号，不是法律或企业规则编号。

对每一单元记录：要求验证的命题、所需字段/资料、已取得事实、缺少事实、是否需要会外总体或执行证据。不能因为当前包方便验证某几个字段，就把未覆盖要求删除。

### 第 4 步：先判断可比性，再进行字段比较

逐对核验以下条件：同事项是否成立；是否同一阶段、同一属性和同一有效版本；同一法律主体、相对方和标的；金额单位、币种、含税/不含税、总额/本次/年度/单项/累计、上限/估计/实际、比例基数是否相同；时间是拟定、召开、签发、送达还是实施；决定中的条件、否定、范围、期限、附带要求是否保留。

比较必须写明比较命题，不能只输出“金额不同”。例如，“申请金额与决议批准金额数值相同”与“纪要准确转述会议最终批准金额”是两个不同命题。原文单位不同但可按确定换算关系统一时保留换算过程；没有依据的汇率、税率、累计范围和时间精度不自动换算。缺少限定语义时补证，不强行比较。amount_basis 是金额性质，scope_raw 是事项/标的范围，stage 是业务阶段；“投资上限”不能填入事项范围。发现错位退回对应路新上下文重提，不由judge补写。condition.content 须有原文明示约束语境，普通同意上会意见、分析假设/局限不能自动作为实施前提。

| comparison.result | 使用条件 | 后续处理 |
|---|---|---|
| consistent | 比较命题和口径清楚，证据支持所选比较关系成立，如等值、限额以内或满足先后关系 | 仍需检查规则要求；比较成立不证明整体合规 |
| different | 相关属性及口径可比较，有证据显示所选关系不成立，如应相等的值不同或实际值超过比较上限 | 说明差异是调整、版本差异还是待核对转述；不直接定偏差 |
| insufficient | 关联、口径、版本、关键原文等不足，尚不能可靠比较 | 点明缺项及最小补证 |
| not_comparable | 已确认属于不同属性、不同阶段或不应相等的两个命题 | 说明不可直接比较原因，可另建合法的过程变化比较 |

同事项仍可能 not_comparable。金额申请与金额批准处于不同属性，不能用“二者必须一致”判定；如果明确比较的是批准对申请的调整，使用 `operator=change_trace` 记录各阶段原值、调整方向和依据，不附加两阶段应当相等的义务。纪要签发日期晚于会议召开日期，本来是不同事件时间，不是日期失真。具体输出使用角色契约中的 links、comparisons 与 decisions，分别引用 link_ids、comparison_ids 和实际 rule_id；没有必要比较的规则可以直接核验原文，不强造比较。

### 第 5 步：从比较进入规则判定

采用以下顺序，不按疑点强弱挑选结果：

1. 规则来源、效力、解释或适用条件未确认：规则待确认，并保留已知事实与证据缺口。
2. 规则明确，事项事实不足以确认是否适用：证据不足。
3. 有证据证明不满足适用条件：不适用，并写排除依据。
4. 规则适用，关键事实、关联或原文未核实：证据不足。
5. 关键证据支持要求全部满足，反证和例外已检查且无未解决重大矛盾：符合。
6. 可定位证据证明具体要求未满足，关键前提成立且有关例外、反证已排查：存在偏差，交人工确认。

五种业务 result 仅为“符合 / 存在偏差 / 证据不足 / 不适用 / 规则待确认”。不得把 comparison 的四值、模型置信度或 completed/partial 状态混入业务结果；不得把存在偏差直接升级为一般、重要或重大缺陷。

### 第 6 步：核对原件、反证与例外

对符合、存在偏差、不适用均回看关键规则原文和事实原文，记录真实读取状态。source_checks 每条 quote 仅一个连续原文片段；不连续行分条并分别定位。原件与OCR/裁切派生件分别核对版本、hash及映射，不能把派生件版本当原件版本。发言记录摘要与纪要来源于同一底稿，不算两份独立佐证。表格空白、OCR 漏字、材料未提供、文件标题缺少某词不能证明程序没有发生。

发现提取遗漏或误读时，只记录原件位置及中性复查问题，由主控向对应路发起新 run；原路只收到获准原件和中性问题，不收到其他路答案。judge 不改 records、不补造 item_index，不以自己的临时摘录绕过独立提取后直接完成受影响的确定性判断。

### 第 7 步：单列业务线索、覆盖范围并交复核

把已有适用规则可判断的问题放入 decisions；把需了解业务前提、测算和执行事实的疑点放入 leads。实际触发已转入CONTROL时，lead_scan仍为lead_found并用linked_decision_ids链接同run同事项判定，可不再造重复lead；去重不能改写成no_signal_in_scope。两类成果与扫描命中分别计数，不把关联次数当缺陷数。每条 lead 有原文事实、问题原因、中性问题、最小补证及管理领域；没有材料基础则不输出。

逐一对账 coverage：做了哪些单元、哪些材料不足、哪些规则待确认、哪些获准单元尚未处理、哪些范围从未授权。提交复核后由评价人员确认事实、规则解释及最终认定。存在未读的获准可读材料或未做检查时用 partial；已完成核对并明确缺少必要材料的单元可以完成“证据不足”，两者不能混用。

## 三、14 项可执行测试卡

以下每卡的“偏差充分条件”均以前述 G1、G2、关键原件核对、关联确认和反证排查完成为前提；未达此条件不得据卡名定偏差。字段以字典1.0为准；具体值和限定信息读取 raw、normalized、qualifiers，不新造提取字段。同名字段通过提取角色、run_id、原始事实性质及阶段区分来源，不能因为名称相同就合并。卡中执行凭证、总体台账等会外资料，须另经主控确认范围和提取路由，不能强塞给四路会议提取者。

### T01 事项范围、权限与决策性质

- **目标与触发**：识别已纳入本次范围的事项应由谁以何种权限处理；对所有选定事项执行，包括可能低于门槛者。
- **所需字段/材料**：`meeting.entity`、`meeting.body`、`agenda.title`、`matter.code`、`matter.project`、`matter.counterparty`、`proposal.action`、`financial.amount`、`proposal.budget`、`decision.content`；章程、事项清单、授权及当时有效的金额计算规则。
- **判断操作**：先辨主体和行为性质，再分事项类别和阈值；判断该会是建议、前置研究、最终决策还是备案。累计事项按已确认口径重算；不同金额属性分别保留。
- **偏差充分条件**：已证明具体事项触发明确权限要求，而作出实际决定的主体不具备该权限或越过其有效授权边界，且无可适用的授权、替代或例外。
- **证据不足**：不清楚事项归属、金额含义或会议行为性质；缺少决定原件。权限来源或阈值本身不清则为规则待确认。
- **例外/反证**：查历史授权、专项授权、保留事项、仅研究不决策、关联事项累计调整；有会议纪要不等于已具备最终权限。
- **规则参数**：P01—P03、P05；参考来源 S02、S03，均须转为适用规则。

### T02 明确要求的前置程序和先后顺序

- **目标与触发**：只对规则要求前置研究、审查、听取意见、报批或批准后实施的事项核验路径。
- **所需字段/材料**：`meeting.body`、`meeting.time`、`matter.code`、`matter.project`、`approval.action`、`approval.acted_at`、`history.reference`、`history.event_at`、`decision.content`、`condition.content`；适用清单、前置程序原件及明确的交叉引用。
- **判断操作**：把规则拆成事件及必要先后关系，按同事项、同阶段和内容范围核对；日期同日而无时间顺序时不得推定先后。分别核验各主体职责，不补上未规定节点。
- **偏差充分条件**：所需前置程序及发生顺序明确，证据直接证明决策或实施已先发生、前置程序后发生或未履行，且无合法替代/例外。
- **证据不足**：只获得后续纪要、缺少前置记录，或无法确认两个材料是同事项。清单边界不明为规则待确认。
- **例外/反证**：查涵盖本事项的既有专题决定、有效授权及后续调整范围；不得把事后补做自动当成已满足事前要求。
- **规则参数**：P01—P04、P11；参考 S03、S04。

### T03 通知、议程与决策材料提供

- **目标与触发**：对具有事前告知或材料提供要求的会议/议题，核验对象、时间和内容。
- **所需字段/材料**：`meeting.time`、`agenda.title`、`agenda.number`、`notice.issued_at`、`notice.received_at`、`document.issued_at`、`schedule.distribution`、`schedule.change`、`proposal.action`；通知原件、收件范围、实际送达/可获取记录、材料目录和补发记录。
- **判断操作**：区分制文、签发、发送、送达及实际开会时间；逐议题核对应收人和该版材料。只在规则确定起算点、单位及例外时计算期限。
- **偏差充分条件**：应告知/供料对象和时限明确，可靠记录证明相关人员未按要求获得材料或实际间隔不足，且适用的补充程序未满足。
- **证据不足**：只有通知签发日期、无发送/送达依据；只见目录而不能证明材料曾提供。未填“N天”不能按常识定逾期。
- **例外/反证**：查更早有效通知、补发回执、系统访问记录、临时议题规则和合法紧急程序；事后参会签字不能当然证明提前收料。
- **规则参数**：P06、P10；参考 S03。

### T04 议案报审与必要研究论证

- **目标与触发**：对规则明确需要论证、审核或征求特定意见的事项，核验相应程序及其覆盖内容。
- **所需字段/材料**：`proposal.action`、`approval.action`、`proposal.review`、`proposal.analysis`、`proposal.risk`、`financial.amount`、`proposal.budget`、`condition.content`、`statement.opinion`、`decision.content`；论证报告、意见书、审批流及版本附件。
- **判断操作**：按事项类别确定所需程序，核对实际承担主体、形成时间、内容是否针对最终提交方案，以及保留意见如何交会议处理；不将材料数量当作论证充分性。
- **偏差充分条件**：明确必须完成的报审/论证程序，经完整流转记录、原件或可靠相反证据确认未在规定节点完成，或实际程序主体明确不符合要求。
- **证据不足**：议案称“已论证”但无原件；所获附件不完整；测算关键假设未说明。论证质量疑问先列线索，不能仅凭模型不认同商业判断定偏差。
- **例外/反证**：查覆盖同版本方案的既有论证、可替代意见及经规则允许的豁免；不得虚构所有事项都要法务、专家或职代会三类审查。
- **规则参数**：P04、P07；参考 S03。

### T05 出席资格与议事人数

- **目标与触发**：对已确认出席/表决资格及人数要求的会议和议题开展核验。
- **所需字段/材料**：`meeting.body`、`meeting.time`、`attendance.person`、`attendance.count`、`recusal.content`、`voting.count`、`voting.expression`；当时有效成员名单、任职变更、签名、远程参会或委托材料。
- **判断操作**：分别列应到成员、实到有资格成员、列席人员、委托出席和回避人员；按规则计算会级及议题级人数，不把列席、主持、记录员自动计为表决成员。
- **偏差充分条件**：分母、资格和适用计算方法明确，可靠出席及变动证据证明召开或决定时不达法定/制度要求，且无有效替代安排。
- **证据不足**：只写“有关领导参加”、签名与身份不明、某议题期间离席时间无法确定；规则明确但成员身份、人数或参与事实缺失，也为证据不足。规则规定的分母计算口径或远程/委托适用条件不清，才为规则待确认。
- **例外/反证**：查成员调整生效日、允许的远程参会、有效委托和回避后计算方式；签名缺失不直接证明未参会。
- **规则参数**：P08、P09；参考 S03。

### T06 逐人表达、逐项讨论与主持结论

- **目标与触发**：仅对已确认需要逐人表达、逐项研究或特定发言顺序的适用会议核验过程。
- **所需字段/材料**：`agenda.title`、`agenda.number`、`attendance.person`、`statement.opinion`、`decision.content`；完整原始记录、可访问的原始载体及严重分歧处理材料。
- **判断操作**：逐议题区分汇报、讨论意见、提问与结论性意见；将发言顺序和决定过程分别核对，不能把主要负责人开始主持/说明议程当作已先发表结论。
- **偏差充分条件**：完整、可信的过程证据明确显示违反已确认表达、讨论或结论顺序要求；严重分歧处理有明确规则时，证据证明该触发条件成立且规定程序未履行。
- **证据不足**：只有简化纪要或摘要，无法还原发言；未记某人意见不能直接证明其没发言。可另按 T09 检查记录义务。
- **例外/反证**：查补记、录音对应片段、依法允许的程序及“严重分歧”的适用解释；不得把一般不同意见自动视为严重分歧。
- **规则参数**：P07—P09；参考 S03。

### T07 表决方式、票数与决定形成

- **目标与触发**：事项进入表决/形成决定且存在可执行表决要求时开展。
- **所需字段/材料**：`attendance.person`、`attendance.count`、`voting.count`、`voting.expression`、`decision.content`、`recusal.content`；表决票、计票表、明确的议题处理结果和相应规则。
- **判断操作**：逐事项核对表决方式、有效人数、赞成/反对/弃权及未参加表决；按已确认基数和比例计算，区别提议、讨论倾向、原则同意、通过、否决和暂缓。
- **偏差充分条件**：可靠表决证据和计算口径明确，未达到要求却被记录或宣告为通过，或采取明确不被允许的决定方式且不存在例外。
- **证据不足**：仅“原则同意”而无能满足规则的过程证据；票数与人数冲突未核清；无逐项结果不能自行平均或推定全体一致。
- **例外/反证**：核对允许的表决形式、重新表决、有效更正与回避扣除；不能把“无人反对”自动当作满足任意比例规则。
- **规则参数**：P08—P10；参考 S02、S03。

### T08 利益关系识别与回避执行

- **目标与触发**：已有材料显示可能存在规则规定的回避关系，或本次明确纳入利益关系申报核验。
- **所需字段/材料**：`matter.counterparty`、`history.reference`、`attendance.person`、`statement.opinion`、`voting.count`、`voting.expression`、`recusal.content`；关系申报、必要且获准的关系证明、回避决定及人数计算材料。
- **判断操作**：先确认关系事实和对应回避规则，再核对需回避的人、阶段及行为；区分说明事实、列席说明、参加讨论、参与表决，遵守最小必要资料范围。
- **偏差充分条件**：已证实关系符合明确回避条件，相关人员实际从事被禁止参与的具体行为，且无合法适用例外。
- **证据不足**：仅姓名相同、传闻或未填申报表，不能推定关联关系或利益输送；回避记载缺失但行为事实不明时补证。
- **例外/反证**：查关系存续期间、身份误认、人员在该议题前退场及规则许可说明情况；不得把回避本身认作违法或偏差。
- **规则参数**：P09；参考 S03。

### T09 原始记录、签认和档案留存

- **目标与触发**：规则要求记录特定要素、签认或归档时，核验相应留痕义务。
- **所需字段/材料**：`meeting.entity`、`meeting.body`、`meeting.number`、`meeting.time`、`attendance.person`、`statement.opinion`、`voting.count`、`voting.expression`、`decision.content`、`condition.content`、`follow_up.action`、`document.number`、`document.issued_at`、`document.signature`；完整记录、附件目录、档案台账及检索结果。
- **判断操作**：分开检查记录内容、签认要求和归档行为；先确认本次取得的是完整原件还是节选。通过获准档案范围、责任人说明和补查确认区分“未提供”与“未形成/未留存”。
- **偏差充分条件**：明确留痕义务适用，完整原件或已核实的完整档案范围证明应记内容确未记录、应签认确未完成或应归档确未归档；分别表述具体缺口。
- **证据不足**：只获得纪要、扫描缺页、附件未移交、档案检索范围不明；均不能直接认定记录不存在。
- **例外/反证**：查独立表决附件、续页、电子原件和有效替代载体；材料原先存在但本次未提供，不按未形成定性。
- **规则参数**：P12；参考 S03，底稿方法参考 S05。

### T10 原始会议结论与纪要/决议传达的一致性

- **目标与触发**：已关联同会议同事项且存在原始会议结论与纪要/决议时，核验最终传达是否准确保留关键内容。
- **所需字段/材料**：原始记录与纪要两路各自的 `decision.content`、`condition.content`、`financial.amount`、`follow_up.action`、`follow_up.owner`、`follow_up.due_at`，以及 `document.amendment`、`proposal.action`、`history.reference`、`document.number`、`document.issued_at`、`document.version`；完整记录、正式纪要、合法更正及后续决定。
- **判断操作**：逐项比较决定性质、主体/标的、金额及口径、条件、范围、期限、责任和保留事项；按第 4 步输出比较结果。将申请到批准的调整与记录到纪要的转述分开。
- **偏差充分条件**：准确记录/传达或不得擅改的适用规则明确，已核实同阶段有效版本的最终会议结论，正式纪要遗漏或改动影响授权边界的关键内容；已核实应覆盖的相关版本与决定范围，未发现能够解释该差异的有效更正或新决定。
- **证据不足**：原始记录尚未完成签认、缺续页、正式版本不明、更正未取得或关键限定语无法辨认；比较可为 insufficient，业务为证据不足。
- **例外/反证**：不改变实质的摘要、单位等值换算、撤回草稿、后续有效重新决策；纪要简化个别讨论不当然构成结论失真。
- **规则参数**：P05、P11—P12；参考 S02、S03。

### T11 紧急临时决定、临时议题及事后程序

- **目标与触发**：材料载明紧急、临时、先行决定、事后报告/追认，或以此解释未走通常流程时开展。
- **所需字段/材料**：`history.reference`、`history.event_at`、`approval.action`、`approval.acted_at`、`meeting.time`、`agenda.title`、`decision.content`；紧急原因、临时权限、实际事件时间、报告和追认材料。
- **判断操作**：分别测试紧急条件、临时决定权限、应有记录、事后报告及追认。通常程序和紧急程序分别对照，不能因为存在追认就抹去事前条件问题。
- **偏差充分条件**：合法适用规则明确，事实证明不满足紧急条件仍使用例外，或明确要求的事后程序超过可确定期限仍未履行；未履行需有充分检索或直接证据。
- **证据不足**：只有“情况紧急”描述、追认议题关联不清、没有明确起算事实；“及时”含义待解释时不能擅造固定天数。
- **例外/反证**：查获准的特殊紧急规则、报告回执、非同一事项误配及有效追认范围；紧急不当然代表违规，也不当然豁免全部要求。
- **规则参数**：P06、P10、P12；参考 S03。

### T12 附条件决议、责任落实与执行时点

- **目标与触发**：记录/纪要带有前置条件、暂停条件、后续报告、期限、责任或执行边界，且本次授权跟踪执行时开展。
- **所需字段/材料**：`decision.content`、`condition.content`、`condition.due_at`、`follow_up.action`、`follow_up.owner`、`follow_up.due_at`、`proposal.analysis`、`proposal.risk`；条件完成证据、验收/确认、合同生效、实际下单、付款和实施记录等获准会外资料。
- **判断操作**：逐条辨明“实施前满足”“实施后报告”“授权范围内细化”等性质；确定条件责任人、验收主体和真正实施节点。先核实实际发生，再比较先后与边界。
- **偏差充分条件**：适用决议及执行要求清楚，可靠证据证明实施发生于必须先满足的条件完成之前、已超出授权范围，或到期的明确义务未履行，且无有效调整/延期。
- **证据不足**：只有议案、会议记录和纪要，没有执行凭证；不能由无条件纪要推断已签约、已付款或已造成损失。
- **例外/反证**：查条件实际早已完成但未归入会议包、只开展被允许的准备工作、经授权延期、新决议及暂停通知；后续义务不误当实施前提。
- **规则参数**：P11、P13；参考 S03。

### T13 主体、标的、金额和方案重大调整

- **目标与触发**：材料出现决议后对象、范围、金额、资金来源、技术路线或条件变化，且规则规定特定调整须重履程序时开展。
- **所需字段/材料**：`matter.project`、`matter.counterparty`、`proposal.action`、`financial.amount`、`proposal.budget`、`history.reference`、`decision.content`、`condition.content`、`document.amendment`；原决议、变更申请、后续决定及实际实施版本。
- **判断操作**：先建立同事项版本链，再按有效规则确定何种变化是重大/越权；区分会前调整、会上决定调整、会后执行变更和纪要更正。不同属性金额不能机械算增长率。
- **偏差充分条件**：实际变更触发明确的重新决策要求，可靠证据证明已按变更实施而规定程序未在应有时点完成，且不属于有效授权调整范围。
- **证据不足**：只有新版申请、无法证明实施；无法关联前后方案或重大调整阈值不明。阈值未定时规则待确认，并可保留有依据的线索。
- **例外/反证**：同一主体更名但身份不变、授权上限内细化、已获批准的替代方案、有效新决定；不得把所有变化一概视为重履程序义务。
- **规则参数**：P03、P05、P11；参考 S02、S03。

### T14 会外业务总体反查与漏报/规避线索

- **目标与触发**：本次范围包括“应上会未上会”或全年事项完整性，且已获准取得可核验业务总体时开展。
- **所需字段/材料**：四路事项标识及决定字段；独立于已上会资料的合同、投资、资金、担保、任免、重大变更等适用业务台账及必要明细；对应期间会议总目录、规则清单和总体调节表。
- **判断操作**：先核实总体范围和完整性，再按规则筛选触发事项，反向查会议/决定；按实际选样方法记录分母与排除原因。临界金额、同项目多批次只能触发累计口径核验或线索，不自动认定拆分。
- **偏差充分条件**：具体业务已发生并明确触发必须决策要求；经可靠关联、完整相关会议/决策档案和补查确认未履行规定程序，且没有授权、合并决策或合法例外。
- **证据不足**：只有已上会会议包、业务总体不完整或尚未核对全部相关决定；“搜索未命中”不足以证明漏报。选样未覆盖部分列范围限制。
- **例外/反证**：查纳入年度/框架决议且覆盖具体事项的授权、其他合法决策载体、历史决定、取消事项及无须再次决策的执行；不以三类会议数量不等判漏报。
- **规则参数**：P01—P05、P10、P14；范围与取证方法参考 S05。

## 四、第三层业务线索：从材料事实提出可检验问题

程序测试之外，只有出现以下事实触发时才输出相应线索。此表是提问设计，不设统一财务指标、商业正确答案或违法推定。对方解释只作为新证据线索；须取得对应材料并核对，不以口头解释自动销项。

| 已提取事实触发 | 可检验的中性问题 | 最小补证及可能解释 |
|---|---|---|
| 议案依赖某需求、产量、价格或利用率，但附件未说明取值时点/依据 | 本次决定所采用的关键假设来自何项数据、形成于何时，是否与该版方案一致？ | 测算底稿、数据来源、版本页；可能是引用附件漏交或沿用已批准测算 |
| 同方案摘要与明细的金额、建设范围或收益口径有冲突 | 摘要与明细分别属于哪一版、何种范围；会议实际审议哪套数据？ | 版本对照、提交目录、会议使用稿；可能为范围变化或汇总口径差异 |
| 明细已有大幅敏感变量变动，而结论仍沿用旧收益/偿债表述 | 变量变化对结论的影响是否在会议材料中更新，是否需要补充说明？ | 更新测算、敏感性分析或已有论证；不要求所有事项一律制作特定模型 |
| 议案称有多个方案或相对方，但未见选择理由 | 当时选择当前方案的依据是什么，替代方案是否仍可行或已被排除？ | 方案比选、技术/价格依据、评审意见；可能存在无法替代的技术条件 |
| 申请引用年度预算，拟承诺金额却涉及跨期或不同主体 | 对应预算科目、年度、承担主体及已占用额度如何衔接？ | 获批预算、调整/额度占用、分期安排；预算额度与现金支付能力分开核对 |
| 方案以融资、回款或专项资金到位为前提，材料显示到位时间晚于拟实施时间 | 是否存在过渡资金安排，哪些承诺在资金到位前生效？ | 现金计划、融资条件、合同生效及付款节点；不能由资金时间差推定资金链风险已实现 |
| 决定载明补测算、取得许可或完成审查后实施，但纪要/后续描述省略条件 | 条件目前如何完成并由谁确认；实际实施节点是否已发生？ | 条件完成证据、确认记录和执行凭证；可能已满足但未归档，不能推断已违规付款 |
| 方案相对方、项目范围或资产标的在后续材料改变 | 变化是更名、分包安排、方案优化还是交易主体/实质标的替换；依据是什么？ | 身份连续性证明、变更说明、授权和后续决定；先确定实质变化再判断程序 |
| 材料出现“已签订”“已启动”但会议表述为申请批准 | 所称行为是意向、准备、附条件签署还是已经生效履行，实际时间如何？ | 合同生效条款、订单、验收、付款及授权；不以某个动词直接推定先实施后决策 |
| 同项目出现多次接近门槛的采购/支付/投资记录 | 各次业务是否相互独立，适用规则要求按何期间、项目和对象累计？ | 总合同、采购需求、项目预算、分批原因、累计规则；不能只凭金额形态认定规避 |
| 会上对风险、异议或后评估提出明确处理安排，后续材料未展示闭环 | 哪些措施已落实，责任、完成节点和效果如何被确认？ | 风险台账、落实报告、后评估及整改证据；仅缺报告不能直接证明未处理 |

线索输出应能还原为：“材料 A 在位置 X 记载事实 F；材料 B 在位置 Y 记载事实 G/本次未提供某证据；需要核实问题 Q；请补 D”。不写“明显不合理”“疑似利益输送”“必然损失”等无充分依据的标签。需要专业测算、工程判断或法律解释时，标明建议交相应专业人员核验。

## 五、coverage、选择范围与结果外推

### 1. 三个分母分别登记

| 分母 | 最少登记内容 | 可得出的结论边界 |
|---|---|---|
| 获准资料范围 | 已收到/未提供的会议包、各路文件及版本、缺页/不可读范围 | 只说明本次来源覆盖 |
| 本次检查范围 | 选取会议和事项、规则、选择方法、检查单元、已处理/未处理 | 只说明样本及规则执行结果 |
| 业务/会议总体 | 期间、主体、总体来源、记录数/金额口径、完整性核验与调节差异 | 经核实才可能支持漏报测试及有限外推 |

总体未知时写“总体未核实，无法计算覆盖比例”；不以收到的会议数当全年会议总数。只检查已上会样本，即使全部符合，也不能推论全年无漏报、无规避或企业整体内控有效。

### 2. 选择方法与遗漏控制

- 执行本次确认的全查、随机/系统抽样、分层抽样或定向选样；主控和评价人员确认方法、总体及范围。模型不擅自缩样，不为凑固定比例创造样本量。
- 风险定向样本可关注金额大、条件复杂、紧急、重复审议、重大调整和跨期事项，同时明确其选择偏向；不能把定向样本的偏差率当总体偏差率。
- 逐会议列出全部已识别议题及处理状态；撤回、延期、合并、拆分议题保留轨迹。未关联不等于漏报；未选样不等于符合。
- 各路 coverage、事项关联、comparison、decisions 和 leads 分别对账。某一检查结果可能引用多个比较，某一比较也可能支持多个规则；按实质控制事项去重，不按条目数直接计算缺陷数。
- 补件、重新提取、阅读件/OCR变更和改规则时，按 [工作流](../references/workflow.md) 的 effective_results/invalidation_log 登记新采用、旧保留及被替换单元，沿依赖使旧判断与旧复核失效，仅重做受影响范围。supersedes_run_id 不自动覆盖整轮；主控只登记专业角色给出的采用依据，不静默改事实或结论。

### 3. 对外表述

可写：“在本次取得并核验的 X 场会议、Y 项事项及列明规则范围内，已处理 Z 个检查单元；其余限制见 coverage。”只有真实完成计数后才能填数。

不能写：“全部会议程序符合”“全年未发现漏报”或“决策均有效”，除非该命题有相应已确认范围、完整总体及足够证据支持，且经过评价人员确认。程序符合不等于投资有效、经营正确、会计处理正确或执行无风险。

这些是假设性验收案例，不是真实发现；期望行为用于检查 judge 是否正确执行本逻辑，不能据此称已完成真实业务测试。
